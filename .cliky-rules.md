# Kliky Project Rules & Architecture

This document serves as the ground truth for AI assistants working on the Kliky project.

## Project Overview
Kliky is a cross-platform desktop application (macOS & Windows) that provides mechanical keyboard sound feedback while typing.

- **Frontend**: React (TSX), Tailwind CSS, Lucide Icons.
- **Backend**: Rust (Tauri v2), Rodio (Audio Engine), SQLite (Persistence).
- **Structure**:
  - `/app`: The main Tauri application.
  - `/app/src`: React frontend logic and components.
  - `/app/src-tauri`: Rust backend logic and audio worker.
  - `/website`: Next.js marketing website.

## Architectural Patterns

### 1. Shared Logic (Hooks)
Do not duplicate logic between `Settings` and `Onboarding`. Use shared hooks:
- `useSettings`: Handles global app state, permission checks, and backend synchronization.
- `useShortcutRecorder`: Manages raw keyboard listener lifecycle and modifier bitmask translation.

### 2. Keyboard Shortcut Recording
Kliky uses a custom bitmask for modifiers to ensure cross-platform compatibility:
- **Bitmask**:
  - Cmd/Win: `1`
  - Shift: `2`
  - Alt/Option: `4`
  - Ctrl: `8`
  - Hyper Key (All): `15`
- **Hook**: `useShortcutRecorder.ts` is the source of truth for translating raw events to display strings and saving to the backend.

### 3. State Management
- **Frontend**: State is fetched via `invoke('get_app_state')` and updated via individual `set_x` commands.
- **Backend**: The global `STATE` (Mutex<AppState>) in Rust is the source of truth. It persists to SQLite.
- **Sync**: Use the `state-update` event emitted from Rust to trigger re-renders in the frontend.

### 4. Audio Engine
- Logic resides in `worker.rs`.
- It consumes `KeyEvent`s from an `mpsc` channel.
- Supports "Speed-based Volume Scaling" which boosts volume based on typing frequency (BPM).

## Coding Standards

### TypeScript / React
- **Type Safety**: Avoid `any`. Use the canonical types in `src/types/index.ts`.
- **Readonly Props**: Use `ReadonlyArray<T>` for props passed from `as const` definitions (e.g., navigation items) to avoid mutability errors.
- **UI Components**: Use the established design system (Sidebar, Switch, Button) rather than raw HTML/Tailwind where possible.

### Rust
- **Documentation**: Use `//!` for module-level docs and `///` for function-level docs.
- **Logging**: Prefer `log::info!`, `log::warn!`, and `log::error!` over `println!`.
- **Window Management**: Use `window.rs` to spawn or focus windows to ensure consistency in vibrancy/blur effects.

## Platform Specifics
- **macOS**: Requires Accessibility permissions to monitor keyboard events. Handle these in `lib.rs` and `commands.rs`. Uses `ActivationPolicy` to toggle between `Accessory` (tray-only) and `Regular` (dock visible).
- **Windows**: Uses a generic low-level keyboard hook.

## Common Gotchas
- When adding new settings, ensure they are added to `AppState` (Rust), `PersistentConfig` (Rust), and `AppState` (TypeScript).
- Always clean up the shortcut recorder state by calling `set_recording_status(false)` on unmount.
